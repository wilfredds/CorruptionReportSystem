corruption-watch-ph/

A public reporting site: a citizen picks a department, describes what happened, and can file anonymously; an admin console reviews what comes in. The hard part is not the form — it is making sure nobody but the admins can ever read it.

role
Sole developer — site, admin console, security rules
stack
Firebase · Firestore rules · Vanilla JS · Emulator tests
started
November 2025
status
First project in the repo

$cat problem.md

Reporting corruption is only safe if the report is genuinely private. A form that accepts anonymous submissions but leaves them world-readable is worse than no form at all: it collects exactly the people who most needed protection and puts them somewhere findable.

$cat solution.md

  • A public report form — department, description, optional anonymity — plus an inline help responder for people who are not sure what counts.
  • An admin console that lists submissions and lets a reviewer work through them.
  • Firestore security rules that let anyone create a report and let nobody read one back unless they are an admin.

$cat rules.md

The rules are the product. They are exercised by a test suite that boots the real Firestore emulator and runs assertions as an anonymous visitor, a signed-in non-admin and an admin — 60 assertions across this project and Bike Guide PH, on every push and every pull request that touches either rules file.

The suite was verified to fail, not just to pass. Temporarily loosening one collection to allow read: if true turned five denial assertions red and exited non-zero. A test suite that cannot go red guards nothing — so I made it go red on purpose before trusting it.

$cat honest-notes.md

This is the oldest project here and it shows its age: the behaviour lives in inline <script> blocks inside the HTML, and two JavaScript files sit empty as stubs from a refactor I never finished. The styling leans on a CDN, which is a dependency on someone else's uptime that I would not choose again.

I keep it in the portfolio because it is where I learned the lesson the other four projects are built on: the visible part of an app is rarely the part that protects anyone.
